# Отчёт по исследованию инфраструктуры для локального RAG-ассистента (обновлённый)

**Задача:** Создать тестовый RAG AI-ассистент для демонстрации на MacBook Pro (Intel Core i7 6‑ядерный, 32 ГБ ОЗУ, Intel UHD Graphics 630). Используются только локальные компоненты. Все обрабатываемые документы конфиденциальны и не должны покидать устройство. Модели обязаны обеспечивать качественную работу с русским языком.

**Объём данных:** 30 небольших текстовых документов.

**Целевая аудитория:** Руководство IT-подразделения, оценивающее возможность внедрения корпоративного RAG-решения. Сценарий — PoC-демонстрация на имеющемся оборудовании. Ключевые приоритеты: конфиденциальность, нулевая стоимость, работа офлайн, русскоязычная поддержка.

---

## 1. Сравнение LLM-моделей

| Критерий               | Локальные (Ollama / Hugging Face)                                                                | Облачные (OpenAI / YandexGPT)                               |
|------------------------|--------------------------------------------------------------------------------------------------|--------------------------------------------------------------|
| **Качество ответов**   | Приемлемое для 7B–8B моделей, особенно с тонкой настройкой под русский. Пример: Qwen2.5-7B демонстрирует уверенное владение русским языком на уровне коммерческих аналогов в простых и средних диалогах. | Высокое. GPT-4o-mini и YandexGPT 3 Lite отлично работают с русским, генерируют структурированные и точные ответы. |
| **Скорость работы**    | На 6‑ядерном i7 модель 7B в 4-битном квантовании выдаёт 5–8 токенов/с. Для демонстрации приемлемо, но требует терпения. | < 1 с задержки API, генерация сотен токенов/с. Комфортно для живого диалога. |
| **Поддержка русского** | **Хорошая.** Qwen2.5-7B (обучен на 29 языках, включая русский), Saiga-LLaMA 8B (специализированная русская модель) – оба варианта показывают высокое качество русской речи. | **Отличная.** YandexGPT – нативная русская модель, OpenAI GPT – достойный мультиязычный уровень. |
| **Стоимость владения** | **0 руб.** — открытые веса, запуск локально. | $0,15–0,50/1M токенов (OpenAI). YandexGPT – от 0,02 ₽/1K токенов. Для ~100 демо-запросов несущественно. |
| **Удобство развёртывания** | **Высокое.** Ollama устанавливается одной командой в macOS, модель скачивается автоматически. Требуется лишь выбор квантованной версии (Q4_K_M). | **Среднее.** Нужен API-ключ, стабильный интернет. Для OpenAI из РФ – VPN/прокси. Router.ai снимает часть сложностей, но зависимость от сети остаётся. |
| **Конфиденциальность** | **Абсолютная.** Данные не покидают устройство. | **Нулевая.** Запросы и контекст уходят на внешние сервера – недопустимо. |

**Вывод:** Требования конфиденциальности и офлайн-работы делают локальную LLM единственно возможным выбором. Рекомендованная модель — **Qwen2.5-7B** (через Ollama: `qwen2.5:7b`). Она обеспечивает хорошее качество русского языка, сравнимую с Saiga производительность и простую интеграцию.

## 2. Сравнение моделей эмбеддингов (с фокусом на русский язык)

| Критерий                      | Локальная (Jina Embeddings v3)                                                                 | Облачная (OpenAI text-embedding-3-small)                     |
|-------------------------------|-------------------------------------------------------------------------------------------------|---------------------------------------------------------------|
| **Скорость индексации**       | На 6‑ядерном CPU обработка 30 коротких документов займёт **менее 30 секунд**. Для PoC более чем достаточно. | Зависит от сети и API. Для 30 документов — тоже быстро, но не офлайн. |
| **Качество поиска (рус. яз.)**| **Превосходное.** Jina-v3 входит в топ моделей до 1B параметров, русский язык – один из 30 приоритетных (из 89 поддерживаемых), качество поиска по русскоязычным текстам подтверждено бенчмарками. | Хорошее мультиязычное качество, но уступает специализированной Jina-v3 на русских корпусах. |
| **Требования к памяти**       | ~2.1 ГБ ОЗУ в fp32; при 32 ГБ на ноутбуке остаётся более 15 ГБ свободными – комфортная работа. | Не применимо локально.                                      |
| **Стоимость владения**        | **0 руб.**                                                       | $0,02/1M токенов. Для 30 документов пренебрежимо, но нарушает конфиденциальность. |
| **Конфиденциальность**        | **Абсолютная** – векторизация и поиск только на устройстве.       | Тексты отправляются вовне – не подходит.                     |

**Вывод:** `jinaai/jina-embeddings-v3` — оптимальный выбор для полностью локального RAG на русском языке. Качество поиска значительно превосходит лёгкие модели типа MiniLM, а объём данных (30 документов) полностью нивелирует опасения по скорости и памяти.

## 3. Сравнение векторных баз данных

| Критерий                        | FAISS (рекомендовано)                                         | ChromaDB                                                        |
|---------------------------------|---------------------------------------------------------------|-----------------------------------------------------------------|
| **Скорость поиска / индексации**| **Максимальная.** Прямая работа с индексом в оперативной памяти, оптимизированные SIMD-инструкции для CPU. Для 30 векторов ответ мгновенный. | Хорошая, но содержит дополнительные прослойки (хранение метаданных, API). На микро-объёмах разница незаметна. |
| **Сложность внедрения**         | **Низкая для PoC.** `pip install faiss-cpu`, 5 строк кода — создание индекса, добавление векторов, поиск. Метаданные удобно хранить в отдельном словаре. | Очень низкая. Установка и встроенный клиент. Но требует больше зависимостей и дискового пространства. |
| **Удобство работы**             | **Высокое для простых сценариев.** Полный контроль над структурой индекса. Для демонстрации не нужны расширенные возможности (фильтрация, обновления). | Выше в сложных проектах: автоматическая персистентность, встроенные функции эмбеддинга, фильтры. |
| **Персистентность**             | Ручная сериализация (`faiss.write_index`) – добавляет 2 строки кода. | Автоматически сохраняет состояние на диск.                      |
| **Ресурсы**                     | Исключительно лёгкая: CPU-версия не требует дополнительной памяти, работает в процессе. | Требует чуть больше ОЗУ и дискового пространства под служебные структуры. |
| **Стоимость владения**          | **0 руб.**                                                     | **0 руб.**                                                     |

**Вывод:** Для PoC с 30 документами, где не требуется частая переиндексация или сложная фильтрация, предпочтительнее **FAISS**. Он обеспечивает минимальный объём кода, максимальную производительность и идеально вписывается в концепцию «всё локально и ничего лишнего». ChromaDB остаётся отличным выбором для масштабируемых продуктовых систем.

## 4. Конфигурация «сервера» (MacBook Pro)

Используемое оборудование полностью удовлетворяет требованиям.

- **CPU:** 6 ядер / 12 потоков. Позволяет комфортно выполнять векторизацию (Jina-v3 задействует все ядра) и инференс LLM. Тактовая частота i7 достаточна для генерации 5–8 токенов/с на 7B-модели.
- **RAM (32 ГБ):** Распределение памяти в пике:
  - LLM Qwen2.5-7B Q4_K_M — ~5 ГБ,
  - Jina-embeddings-v3 — ~2.1 ГБ,
  - FAISS-индекс для 30 векторов размерности 1024 — ничтожно (менее 1 МБ),
  - Система, IDE, браузер — ~4–5 ГБ.
  Остаётся более 15 ГБ свободной памяти — никакого свопа.
- **GPU:** Intel UHD Graphics 630 не используется (нагрузка полностью на CPU), что приемлемо для выбранных моделей.
- **Диск:** SSD, обязателен для быстрой загрузки моделей и сериализации индекса.

**Итог:** Имеющийся MacBook Pro — готовая платформа для локального RAG. Никакого дополнительного оборудования не требуется.

## 5. Варианты конфигураций

### Вариант A. Полностью облачный
- **LLM:** OpenAI / YandexGPT (через Router.ai)
- **Embeddings:** OpenAI
- **Vector DB:** FAISS (in-process, как индекс в ОЗУ)
- **Минусы:** Все документы и запросы уходят в облако — категорически не подходит для конфиденциального кейса.

### Вариант B. Гибридный (локальный поиск, облачная генерация)
- **LLM:** YandexGPT / OpenAI
- **Embeddings:** Jina-v3 локально
- **Vector DB:** FAISS локально
- **Минусы:** Промпт, содержащий конфиденциальные чанки, отправляется облачной LLM. Нарушает базовое требование конфиденциальности.

### Вариант C. Полностью локальный (рекомендуемый)
- **LLM:** Ollama с моделью `qwen2.5:7b` (отличная поддержка русского, 4-битное квантование)
- **Embeddings:** `jinaai/jina-embeddings-v3`
- **Vector DB:** FAISS (in-memory, с optional сохранением на диск)
- **Инфраструктура:** MacBook Pro, без внешних затрат.
- **Плюсы:**
  - 100% конфиденциальность — ни один байт не покидает устройство.
  - Полная офлайн-работа.
  - Высокое качество поиска и генерации на русском языке.
  - Индексация 30 документов — менее 30 секунд, поиск — доли миллисекунды.
  - Нулевая стоимость владения.
  - Минимальный и прозрачный код (FAISS + словарь метаданных).
- **Минусы:**
  - Скорость генерации LLM (5–8 токенов/с) — диалог требует небольших пауз.
  - Модель Jina-v3 занимает ~2.1 ГБ ОЗУ, что всё ещё комфортно в рамках 32 ГБ.
- **Итог:** Лучший баланс безопасности, качества русского языка и простоты для демонстрации.

### Вариант D. Внешний GPU-сервер
- Избыточен для показа на одного пользователя. Стоимость аренды начинается от 300 $/мес, требует выделенного администрирования. Не соответствует цели «тестовый показ на ноутбуке».

## Итоговая рекомендация

Для задачи создания тестового RAG-ассистента с упором на конфиденциальность, русский язык и использование только локальных ресурсов MacBook Pro рекомендуется **Вариант C** со следующим стеком:

- **LLM:** `qwen2.5:7b` (Ollama). Модель уверенно работает с русским языком, поддерживает системные промпты и инструктивное взаимодействие.
- **Эмбеддинги:** `jinaai/jina-embeddings-v3`. Лучшее на сегодня решение для русского языка в открытом доступе; на 30 документах производительность CPU более чем достаточна.
- **Векторная база данных:** **FAISS**. Обеспечивает молниеносный поиск, не добавляет лишних зависимостей и полностью контролируется кодом демонстрации.
- **Окружение:** Python 3.11, `faiss-cpu`, `sentence-transformers` (для загрузки Jina-v3 по HF-пути), `ollama`.

Такая конфигурация позволит эффектно продемонстрировать работу полностью локального RAG-ассистента, отвечающего на русском языке по конфиденциальным документам, без единого обращения к внешним сервисам и без каких-либо затрат.
